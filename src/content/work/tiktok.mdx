## Context

Direct messages in TikTok run on an in-house instant-messaging SDK, and TikTok Shop and Lemon8 build on the same SDK. I joined the IM SDK team in Social Foundation in July 2025 and work on the iOS client in Objective-C and Swift.

Messaging looks simple from the outside: you type, it arrives. Underneath, a phone drops between networks, a real-time connection expires, pushes arrive out of order, and people switch accounts. My work is making those cases invisible to the person sending the message.

## What I built

**Automatic resend for failed sends.** When a message fails because of a client-side network error, the client now retries it without the user having to tap anything.

**A fallback when the real-time connection's credentials expire**, so a send that would have failed goes through another path instead.

**A client-side buffer for out-of-order pushes.** Real-time messages that arrive out of sequence are held and put back in order, instead of triggering a fresh fetch from the server each time.

**Privacy checks for account switching.** Message traffic is checked against the signed-in user, with monitoring that flags a session bound to the wrong account.

**One interface for conversation data.** I consolidated a sprawl of conversation APIs into a single SDK interface, so feature teams across TikTok messaging have one place to query.
