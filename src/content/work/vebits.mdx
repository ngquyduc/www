## Context

Drivers and riders around Singapore send their dashcam footage to Vebits. The system splits those videos, and the feeds from route cameras, into images, and a defect-detection model looks for road defects in them: about 500k images on a typical day. The defects end up on a map in an Angular web app with a Django backend and MongoDB, used for urban infrastructure management.

I didn't build that system. I joined it for a summer, on the backend.

## What I did

**Geospatial query enhancements in Django**, which brought data processing for those queries down from 300 ms to 200 ms.

## Decisions

<Callout kind="Decision" title="Measure the slow queries before changing them">
  I timed the geospatial queries first, changed them, then timed them again the same way. That before-and-after is where the 300 ms to 200 ms comes from, and it kept the work on the queries that were actually slow.
</Callout>

## In hindsight

I'd set up slow-query monitoring before optimizing anything. I found the slow geospatial queries by profiling by hand, and a dashboard would have shown them sooner and kept watching once I'd left.
