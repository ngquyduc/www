## Context

dConstruct builds a surveillance system that works on point clouds. Operators connect sensors, watch a live 3D view and play back recorded footage. It is a small startup, so I worked across the whole stack rather than inside one team.

Before the rebuild, training a new operator on the system took two days.

## What I built

**Endpoints in C++17 and SQLite 3, compiled with Emscripten,** for sensor connections, live view and video playback. Together they cut latency for real-time surveillance by 20%.

**The operator UI in SolidJS and TailwindCSS**, responsive across the screens operators actually use. Training a new operator now takes one day instead of two.

**A C++ PDF report generator** packaged as a library, so reports come out the same way every time. One project uses it so far.

## Decisions

<Callout kind="Decision" title="Compile the C++ for the browser instead of rewriting it">
  Some of the logic the UI needed already existed in C++. Rather than port it to JavaScript, I compiled it to WebAssembly with Emscripten, so the browser and the services run the same code. The trade-off is a bigger download and harder debugging in the browser, in exchange for one implementation to test and keep correct.
</Callout>

<Callout kind="Decision" title="SQLite for the system's own data">
  The system ships as a self-contained installation, so an embedded database made sense: no database server to install or run, and one file to back up. SQLite allows one writer at a time, which was fine for the system's records but is the first thing to revisit if writes grow.
</Callout>

## In hindsight

I'd write down baseline numbers for every endpoint before changing any of them, with a script anyone can rerun. Rebuilding the "before" after the fact is slow, and a baseline from day one gives every change its number for free.
