Hero demo anatomy: what users see vs what I see

  1. Phone (left): 360×720, 32 px radius, skin follows the site theme. Header (back, avatar, invented contact “Remy”, presence, call, more), pinned banner, scrollable thread, composer (camera, input, mic, sticker, +, send).
  2. Message types: text (with reply-quote and reaction row), sticker (invented SVG art), photo, 3-photo album, voice (play, waveform, time), shared video card (reference only), link preview card, system line, date divider.
  3. Long press: 450 ms on any type opens Pin/Unpin · Reply · 😂 · Cancel; Enter does the same from the keyboard; a short tap shows a hint pill. The + tray sends each type.
  4. Engineer panel (right): dark instrument; SIMULATED badge; PLAYBACK ×3 or INSTANT; connection dot; Flaky network and Offline toggles.
  5. Per-type pipeline: e.g. photo LOCAL PREVIEW → COMPRESS → UPLOAD → SEND MEDIA REF → ACK → DELIVERED → SEEN; video PICK → RESOLVE REFERENCE → SEND REF ONLY → …; exception chip for upload %, queued, retry, failed.
  6. Event log: last 10 events, “+N ms” since the action, lanes UI · DB · NET · SYNC in their own colours. Record grid: type, client id, server seq, status, payload, attempts, outbox, pins.
  7. Mobile: under 720 px the panes become two tabs with shared state.
  8. Honesty: SIMULATED, simulated ms and sizes, invented conversation and art, example domains, no brand assets, “not any company's implementation”.
  9. States: see the states board (13 panels + 2 mobile tabs).
